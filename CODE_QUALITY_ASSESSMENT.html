Summary: The codebase has strong feature separation across modules and good architectural boundaries (routes split by concern). However, it suffers from pervasive duplication of business logic, timestamps, and template scaffolding. Security gaps (CSRF, XSS) and error handling weaknesses (no transaction rollback, partial writes on failure) are the most urgent fixes. No test infrastructure exists.

Overall Assessment: High Risk — Suitable for single-user/small team. Not production-ready for scaling without addressing data-integrity issues and security gaps.

Critical Issues (Fix Immediately)

Critical CSRF Tokens Missing From All Forms
Risk: Every state-changing operation (create bill, refund, delete product, edit expense) is vulnerable to Cross-Site Request Forgery.
Scope: ~30 POST forms across all templates
Impact: A malicious website can trick a logged-in user into creating unauthorized bills or deleting data.
Fix: Enable Flask-WTF, add CSRF middleware to core.py, insert {% csrf_token() %} in all POST forms.
Affects: All templates with form method="POST"
Critical Stored XSS in onclick Handlers
Risk: User-controlled data (customer names, product SKUs) rendered into JavaScript event handlers without escaping.
Examples:
store_credits.html:87-89 onclick="setCredit('{{ credit.customer_name }}', {{ credit.id }})" inventory.html (API response) variantsList.innerHTML = variants.map(v => `
${v.name} / ${v.sku}
` // NOT ESCAPED ).join('');
Attack: If a customer name contains `'`, it executes in the browser.
Fix: Use |tojson filter in templates. In JS, use escapeHtml() before innerHTML.
Affects: store_credits.html, categories.html, inventory.html
Critical No Transaction Rollback on Multi-Table Writes
Risk: Complex operations write to 4–6 tables without explicit BEGIN/ROLLBACK. If one statement fails mid-flow, partial state corruption occurs.
Examples:
delete_bill: writes to refunds, refund_items, bills, bill_items, products process_refund: writes to 5-6 tables with interdependent logic clean_all_data: deletes 6 tables AND files No rollback on any of these.
Impact: A customer can have a refund recorded but stock not restored, creating inconsistency.
Fix: Wrap multi-table operations in try/except with explicit db.rollback() on error.
Affects: routes_sales.py, routes_inventory.py, routes_admin.py

Backend Issues (Routes & Business Logic)

Duplication & Code Reuse

High Timestamp Hardcoding (51 Occurrences)
Issue: Every INSERT/UPDATE statement uses datetime('now','+5 hours','+30 minutes') directly instead of calling existing now_ist() helper.
Impact: Any timezone/DST logic change requires edits across 6+ files.
Fix: Replace all hardcoded datetime strings with now_ist().isoformat().
routes_sales.py, routes_inventory.py, routes_admin.py (23, 9, 8 occurrences respectively)
High Store-Credit Mutation Duplicated 8x
Issue: Update credit balance + INSERT transaction record is copy-pasted verbatim across 8 locations.
Impact: Any change to credit rules must be made in 8+ places. One forgotten location = inconsistent behavior.
Fix: Extract a single function: apply_store_credit(db, credit_id, bill_id, amount, txn_type, remarks).
routes_sales.py (6x), routes_inventory.py (2x)
High Admin-Auth Guard Duplicated 40+ Times
Issue: Every admin-only route repeats the same guard check instead of using a decorator.
Impact: New admin routes risk forgetting the guard. Centralizing the check is impossible without a decorator.
Fix: Create a @require_admin() decorator in core.py.
All route files

Business Logic & Architecture

High Four Giant Route Handlers (>200 Lines Each)
Issue: create_bill (285 LOC), process_refund (234), profit_loss (225), daily_summary (180) each do 4+ unrelated things.
Impact: Cannot test math separately from DB writes. Cannot reuse logic. Hard to debug.
Fix: Extract business logic into service modules (billing_service.py, refund_service.py).
routes_inventory.py, routes_sales.py, routes_reports.py
High No Input Validation Helper
Issue: Float/int conversion scattered across 10+ routes without try/except. Bare key access causes 500 errors.
Impact: Missing form key or non-numeric input → 500 error (unhelpful).
Fix: Create validation helpers: parse_amount(val, default=0), parse_int(val, default=0).
routes_sales.py, routes_inventory.py, routes_reports.py

Database Performance

High N+1 Query Patterns (3 Locations)
Issue: Queries execute in loops instead of a single JOINed query.
Impact: O(n) round trips to DB. Full-year exports or large bulk operations timeout.
routes_admin.py (low_stock_alerts, admin_sales_summary), routes_reports.py (export_sales)

File Upload Security

High File Upload Vulnerabilities
Risk 1: No MAX_CONTENT_LENGTH → unbounded uploads → disk exhaustion.
Risk 2: Images saved before DB INSERT → orphaned files on error.
Risk 3: Old image deleted before new validation → dangling paths.
Risk 4: Only extension checked, not MIME type.
Fix: Set MAX_CONTENT_LENGTH. Validate file in memory first, then save. Cleanup on error.
core.py, routes_reports.py, routes_inventory.py

Frontend Issues (Templates & JavaScript)

Template Duplication & Organization

High Receipt Logic Triplicated
Issue: Nearly identical invoice rendering in bill_detail.html, bill_thermal.html, rental_deposit_return_receipt.html.
Impact: Changes to invoice layout require edits in three places. Easy to diverge.
Fix: Extract shared partials: _invoice_items_table.html, _invoice_totals.html.
Medium Page-Header Scaffold Duplicated ~40 Times
Issue: Every template inlines its own page-header instead of using {% include %}.
Impact: Change to header styling requires 40+ edits.

JavaScript Modularity

High billing.js Unstructured (631 LOC, No Module Wrapper)
Issue: Global scope pollution (cartItems, currentStoreCredit, etc.). All 30+ functions on window scope.
Impact: No encapsulation. Name collisions. No testability.
Fix: Wrap in ES6 module or class. Use BillingCart class to encapsulate state.
High 850+ Lines of Inline <script>
Issue: Heavy inline scripts in templates (inventory.html ~319, product_form.html ~121).
Impact: No linting, no minification, no caching. Poor performance.

Formatting & Accessibility

Medium Money Formatting Ad-Hoc (137 Instances)
Issue: No custom Jinja currency filter. Template strings sprinkled everywhere with inconsistent symbols (₹, Rs., Rs).
Impact: Inconsistency. Changing format requires 137 edits.
Fix: Create a Jinja filter: {{ amount | currency }}.
Medium Accessibility Gaps
Issue: Icon-only buttons without aria-label. Many labels without for= attributes.
Impact: Screen reader users cannot access forms or understand buttons.
